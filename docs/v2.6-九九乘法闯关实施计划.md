# v2.6 九九乘法闯关实施计划

## 1. 版本目标

v2.6 新增独立于现有“计算训练”的九九乘法闯关模块。孩子通过完整的 `1–9 × 1–9` 乘法坐标表，在逐级减少视觉提示的三种难度下练习乘法，并通过即时反馈和闯关评星了解本局表现。

本版本重点验证“乘法坐标表、分层提示、即时反馈、闯关评星”这一核心玩法，不把乘法题直接塞入现有加减法训练流程。

### 1.1 产品目标

- 覆盖 `1–9 × 1–9` 共 81 道有序乘法题。
- 用统一的 9×9 乘法坐标表承载三档难度，难度越高，可见答案越少。
- 支持 10、20、50、81 题四种单局题量；81 题用于完成整张九九乘法表。
- 每题提交后立即反馈，帮助孩子及时纠正记忆。
- 用正确率和速度生成简单、可理解的一至三星评价。
- 保持平板和电脑端的清晰布局、键盘操作和基础无障碍能力。

### 1.2 非目标

- 不加入缺因数题、除法题、配对题或拖拽题。
- 不设置线性关卡解锁，简单、中等、困难均可直接进入。
- 不保存历史成绩、最佳成绩或长期闯关进度。
- 不提供本局错题回顾、错题重练或乘法专项统计。
- 不接入现有加减法的辅助运算、错误分类、综合评价和错题订正。
- 不修改现有 `practice-records` 存储结构。
- 不在本版本内适配宽度低于 `768px` 的手机小屏。

## 2. 页面流程与路由

模块使用独立页面和路由，避免乘法设置、评分规则与加减法训练互相耦合。

| 路径 | 页面 | 主要职责 |
|---|---|---|
| `/multiplication` | 闯关设置页 | 选择难度和题量，查看难度说明并开始闯关 |
| `/multiplication/session` | 闯关答题页 | 展示乘法坐标表、题目、作答控件、进度、计时和即时反馈 |
| `/multiplication/result` | 本局结算页 | 展示星级、分数、正确题数、总题数和用时 |

首页新增“九九乘法表”入口卡片，与“错题列表”“计算训练”并列。进入设置页后：

1. 选择简单、中等或困难，三种难度始终可用。
2. 选择 10、20、50 或 81 题。
3. 点击“开始闯关”，生成题目并进入答题页。
4. 完成全部题目后进入结算页。
5. 结算页可按原设置重新随机闯关，或返回设置页。

设置、题目、逐题结果和本局结算只保存在当前页面状态与路由状态中。直接访问、刷新答题页或刷新结算页时，如果缺少有效状态，应使用 `replace` 返回 `/multiplication`，不得生成无法追溯设置的新会话。

## 3. 题库、难度与交互规则

### 3.1 完整九九表题库

题库由两个因数分别取 `1–9` 的笛卡尔积构成，共 81 道题：

```text
1×1, 1×2, …, 1×9
2×1, 2×2, …, 2×9
…
9×1, 9×2, …, 9×9
```

交换因数顺序的算式视为不同题目，例如 `3×7` 与 `7×3` 都在题库中。

每局从 81 道题中无放回随机抽取指定数量，保证同一局内不出现重复算式。81 题模式覆盖每个有序组合恰好一次。生成后的题目统一包含：

```js
{
  a: 7,
  b: 8,
  op: '*',
  answer: 56
}
```

简单难度额外生成四个唯一选项。选项必须包含正确答案；干扰项优先使用目标格上下左右相邻口诀的结果以及常见偏差值，最后使用邻近整数补足。所有选项必须为正整数、顺序随机，且不得重复。

### 3.2 乘法坐标表

答题页始终显示完整的 9×9 坐标框架：

- 顶部列标题为第二个因数 `1–9`。
- 左侧行标题为第一个因数 `1–9`。
- 当前题目的交叉格为目标格，并使用明显但不刺眼的高亮。
- 目标格始终留空，不得通过文本、DOM 属性、无障碍名称或隐藏内容泄露答案。
- 非当前提示范围的乘积格保留网格位置但不显示乘积，避免布局跳动。

三种难度使用同一坐标表，只改变可见乘积范围：

| 难度 | 作答方式 | 可见乘积 |
|---|---|---|
| 简单 | 四选一 | 显示目标所在整行和整列除目标格外的所有乘积 |
| 中等 | 数字输入 | 仅显示目标格上、下、左、右实际存在的相邻乘积 |
| 困难 | 数字输入 | 不显示任何乘积，仅保留行列标题和目标格 |

边界目标格只显示真实存在的相邻格。例如 `1×1` 在中等难度下只显示右侧和下方两个相邻乘积，不补虚拟格。

### 3.3 作答与即时反馈

- 简单难度点击一个选项即可提交。
- 中等和困难难度输入正整数后，可点击提交或按 Enter 提交。
- 空值、非整数和非正整数不能提交，并给出简短、儿童可理解的提示。
- 提交后立即锁定本题，不能修改答案或再次尝试。
- 答对时显示绿色成功反馈和完整正确算式。
- 答错时显示孩子的答案与正确算式，不使用羞辱性或强烈警告文案。
- 反馈短暂停留后自动进入下一题；同时提供明确的“下一题”操作，避免孩子必须等待动画。
- 最后一题反馈结束后进入结算页。
- 切换题目时清理上一题的临时输入、选中项、焦点、光束和反馈，但永久保留所有已提交目标格的正确乘积及对错状态。
- 历史格在三档难度中始终可见；当前题、历史格、临时难度提示和隐藏格按此顺序决定显示优先级。
- 非对角线题的交换律对称格只在反馈期间临时显示；只有实际作答的目标格进入历史。若对称格此前已经作答，则保留它原有的历史状态。
- 81 题最后一题提交后整张表全部打开，矩阵完成反馈只播放一次，仍由孩子手动进入结算。

## 4. 计分与评星

### 4.1 本局统计

本局结果至少包含：

```js
{
  settings: {
    difficulty: 'easy', // easy | medium | hard
    questionCount: 10
  },
  total: 10,
  correct: 9,
  score: 90,
  timeSpent: 72,
  averageSeconds: 7.2,
  stars: 3
}
```

- `score = Math.round(correct / total * 100)`。
- `timeSpent` 为从首题可作答到最后一题提交的总秒数。
- `averageSeconds = timeSpent / total`，仅用于评星和结算展示。

### 4.2 星级规则

准确率优先，速度只用于获得三星：

| 星级 | 条件 |
|---|---|
| 3 星 | 正确率不低于 90%，且平均每题用时不超过当前难度目标 |
| 2 星 | 未达到三星，但正确率不低于 80% |
| 1 星 | 完成本局 |

各难度三星速度目标：

| 难度 | 平均每题用时 |
|---|---:|
| 简单 | `≤ 8` 秒 |
| 中等 | `≤ 10` 秒 |
| 困难 | `≤ 12` 秒 |

计时和星级逻辑应实现为纯函数，明确覆盖阈值等于边界、零题防御和异常时间输入。结算页用简短文案说明未获得三星的主要原因，例如“答得很准，再熟练一点就能拿到三星”。

## 5. 页面设计与状态边界

### 5.1 设置页

- 展示三张难度卡片，说明作答方式和坐标提示范围。
- 默认选择简单难度和 10 题。
- 题量使用 `10 / 20 / 50 / 81` 按钮组；81 题说明为“完成整张九九乘法表”。
- 开始按钮是页面唯一主操作。
- 不显示加减法训练的数值范围、运算比例、进退位难度或辅助算法设置。

### 5.2 答题页

- 顶部展示题号、总题数、进度和本局计时。
- 中部以乘法坐标表为主要视觉区域。
- 坐标表下方展示当前算式和作答控件。
- 简单难度的四个选项保持足够大的触控区域。
- 中等和困难难度进入新题时自动聚焦输入框。
- 即时反馈区域使用 `aria-live`，但避免重复播报整张表格。
- 尊重减少动态效果设置；反馈切换不能依赖动画才能完成。

### 5.3 结算页

- 只展示一至三星、分数、正确题数、总题数和用时。
- 提供“再来一局”和“返回难度选择”。
- “再来一局”沿用原难度和题量，重新无放回抽题。
- 不展示逐题列表、错题答案、历史趋势、综合雷达图或订正入口。

### 5.4 数据隔离

- 不调用现有 `savePracticeRecord`。
- 不读取或写入 `practice-records`。
- 不把乘法记录混入现有统计页和历史详情。
- 不增加新的长期成绩 localStorage key。
- 可复用通用计时、随机打乱和运算符显示能力，但乘法题库、矩阵提示、评星与页面状态使用独立模块。

### 交付物

- 提交给低保真原型阶段验证的问题清单。

### 完成标准

- 每个页面的进入条件、主要操作、离开条件和异常回退均有定义。
