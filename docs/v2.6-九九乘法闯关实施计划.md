# v2.6 九九乘法闯关实施计划

## 1. 版本目标

v2.6 新增独立于现有“计算训练”的九九乘法闯关模块。孩子通过完整的 `1–9 × 1–9` 乘法坐标表，在逐级减少视觉提示的三种难度下练习乘法，并通过即时反馈和闯关评星了解本局表现。

本版本重点验证“乘法坐标表、分层提示、即时反馈、闯关评星”这一核心玩法，不把乘法题直接塞入现有加减法训练流程。

### 1.1 产品目标

- 覆盖 `1–9 × 1–9` 共 81 道有序乘法题。
- 用统一的 9×9 乘法坐标表承载三档难度，难度越高，可见答案越少。
- 支持 10、20、50 题三种单局题量。
- 每题提交后立即反馈，帮助孩子及时纠正记忆。
- 用正确率和速度生成简单、可理解的一至三星评价。
- 保持平板和电脑端的清晰布局、键盘操作和基础无障碍能力。

### 1.2 非目标

- 不加入缺因数题、除法题、配对题或拖拽题。
- 不设置线性关卡解锁，简单、中等、困难均可直接进入。
- 不保存历史成绩、最佳成绩或长期闯关进度。
- 不提供本局错题回顾、错题重练或乘法专项统计。
- 不接入现有加减法的辅助运算、错误分类、综合评价和错题订正。
- 不修改现有 `practice-records` 存储结构。
- 不在本版本内适配宽度低于 `768px` 的手机小屏。

## 2. 页面流程与路由

模块使用独立页面和路由，避免乘法设置、评分规则与加减法训练互相耦合。

| 路径 | 页面 | 主要职责 |
|---|---|---|
| `/multiplication` | 闯关设置页 | 选择难度和题量，查看难度说明并开始闯关 |
| `/multiplication/session` | 闯关答题页 | 展示乘法坐标表、题目、作答控件、进度、计时和即时反馈 |
| `/multiplication/result` | 本局结算页 | 展示星级、分数、正确题数、总题数和用时 |

首页新增“九九乘法表”入口卡片，与“错题列表”“计算训练”并列。进入设置页后：

1. 选择简单、中等或困难，三种难度始终可用。
2. 选择 10、20 或 50 题。
3. 点击“开始闯关”，生成题目并进入答题页。
4. 完成全部题目后进入结算页。
5. 结算页可按原设置重新随机闯关，或返回设置页。

设置、题目、逐题结果和本局结算只保存在当前页面状态与路由状态中。直接访问、刷新答题页或刷新结算页时，如果缺少有效状态，应使用 `replace` 返回 `/multiplication`，不得生成无法追溯设置的新会话。

## 3. 题库、难度与交互规则

### 3.1 完整九九表题库

题库由两个因数分别取 `1–9` 的笛卡尔积构成，共 81 道题：

```text
1×1, 1×2, …, 1×9
2×1, 2×2, …, 2×9
…
9×1, 9×2, …, 9×9
```

交换因数顺序的算式视为不同题目，例如 `3×7` 与 `7×3` 都在题库中。

每局从 81 道题中无放回随机抽取指定数量，保证同一局内不出现重复算式。生成后的题目统一包含：

```js
{
  a: 7,
  b: 8,
  op: '*',
  answer: 56
}
```

简单难度额外生成四个唯一选项。选项必须包含正确答案；干扰项优先使用目标格上下左右相邻口诀的结果以及常见偏差值，最后使用邻近整数补足。所有选项必须为正整数、顺序随机，且不得重复。

### 3.2 乘法坐标表

答题页始终显示完整的 9×9 坐标框架：

- 顶部列标题为第二个因数 `1–9`。
- 左侧行标题为第一个因数 `1–9`。
- 当前题目的交叉格为目标格，并使用明显但不刺眼的高亮。
- 目标格始终留空，不得通过文本、DOM 属性、无障碍名称或隐藏内容泄露答案。
- 非当前提示范围的乘积格保留网格位置但不显示乘积，避免布局跳动。

三种难度使用同一坐标表，只改变可见乘积范围：

| 难度 | 作答方式 | 可见乘积 |
|---|---|---|
| 简单 | 四选一 | 显示目标所在整行和整列除目标格外的所有乘积 |
| 中等 | 数字输入 | 仅显示目标格上、下、左、右实际存在的相邻乘积 |
| 困难 | 数字输入 | 不显示任何乘积，仅保留行列标题和目标格 |

边界目标格只显示真实存在的相邻格。例如 `1×1` 在中等难度下只显示右侧和下方两个相邻乘积，不补虚拟格。

### 3.3 作答与即时反馈

- 简单难度点击一个选项即可提交。
- 中等和困难难度输入正整数后，可点击提交或按 Enter 提交。
- 空值、非整数和非正整数不能提交，并给出简短、儿童可理解的提示。
- 提交后立即锁定本题，不能修改答案或再次尝试。
- 答对时显示绿色成功反馈和完整正确算式。
- 答错时显示孩子的答案与正确算式，不使用羞辱性或强烈警告文案。
- 反馈短暂停留后自动进入下一题；同时提供明确的“下一题”操作，避免孩子必须等待动画。
- 最后一题反馈结束后进入结算页。
- 切换题目时更新目标格、可见提示、输入值、选中项和焦点，不保留上一题的交互状态。

## 4. 计分与评星

### 4.1 本局统计

本局结果至少包含：

```js
{
  settings: {
    difficulty: 'easy', // easy | medium | hard
    questionCount: 10
  },
  total: 10,
  correct: 9,
  score: 90,
  timeSpent: 72,
  averageSeconds: 7.2,
  stars: 3
}
```

- `score = Math.round(correct / total * 100)`。
- `timeSpent` 为从首题可作答到最后一题提交的总秒数。
- `averageSeconds = timeSpent / total`，仅用于评星和结算展示。

### 4.2 星级规则

准确率优先，速度只用于获得三星：

| 星级 | 条件 |
|---|---|
| 3 星 | 正确率不低于 90%，且平均每题用时不超过当前难度目标 |
| 2 星 | 未达到三星，但正确率不低于 80% |
| 1 星 | 完成本局 |

各难度三星速度目标：

| 难度 | 平均每题用时 |
|---|---:|
| 简单 | `≤ 8` 秒 |
| 中等 | `≤ 10` 秒 |
| 困难 | `≤ 12` 秒 |

计时和星级逻辑应实现为纯函数，明确覆盖阈值等于边界、零题防御和异常时间输入。结算页用简短文案说明未获得三星的主要原因，例如“答得很准，再熟练一点就能拿到三星”。

## 5. 页面设计与状态边界

### 5.1 设置页

- 展示三张难度卡片，说明作答方式和坐标提示范围。
- 默认选择简单难度和 10 题。
- 题量使用 `10 / 20 / 50` 按钮组。
- 开始按钮是页面唯一主操作。
- 不显示加减法训练的数值范围、运算比例、进退位难度或辅助算法设置。

### 5.2 答题页

- 顶部展示题号、总题数、进度和本局计时。
- 中部以乘法坐标表为主要视觉区域。
- 坐标表下方展示当前算式和作答控件。
- 简单难度的四个选项保持足够大的触控区域。
- 中等和困难难度进入新题时自动聚焦输入框。
- 即时反馈区域使用 `aria-live`，但避免重复播报整张表格。
- 尊重减少动态效果设置；反馈切换不能依赖动画才能完成。

### 5.3 结算页

- 只展示一至三星、分数、正确题数、总题数和用时。
- 提供“再来一局”和“返回难度选择”。
- “再来一局”沿用原难度和题量，重新无放回抽题。
- 不展示逐题列表、错题答案、历史趋势、综合雷达图或订正入口。

### 5.4 数据隔离

- 不调用现有 `savePracticeRecord`。
- 不读取或写入 `practice-records`。
- 不把乘法记录混入现有统计页和历史详情。
- 不增加新的长期成绩 localStorage key。
- 可复用通用计时、随机打乱和运算符显示能力，但乘法题库、矩阵提示、评星与页面状态使用独立模块。

## 6. 实施阶段

### 阶段 1：题库、难度配置和评分模型

- 定义难度、题量、速度目标和默认设置常量。
- 实现 81 道有序乘法题库和无放回随机抽题。
- 实现简单难度四选一生成规则。
- 实现矩阵可见格计算函数。
- 实现本局计分、平均用时和评星纯函数。
- 为所有纯逻辑补齐单元测试。

验收标准：

- 题库恰好包含 81 个唯一有序组合。
- 10、20、50 题均无重复且答案正确。
- 三档难度的可见格严格符合规则，目标答案不会泄露。
- 评分与星级边界测试全部通过。

### 阶段 2：首页入口、路由与设置页

- 首页增加“九九乘法表”入口卡片。
- 注册三个乘法模块懒加载路由。
- 实现难度卡片、题量选择和开始闯关。
- 实现缺少有效会话状态时的路由回退。

验收标准：

- 首页可独立进入乘法模块，不影响原有两个入口。
- 三种难度均可直接选择。
- 题量选择准确传入会话。
- 刷新或直接访问会话、结算路由时安全返回设置页。

### 阶段 3：9×9 乘法矩阵和答题页

- 实现固定布局的 9×9 坐标表。
- 实现三档可见范围和目标格高亮。
- 实现简单四选一及中等、困难数字输入。
- 接入进度、计时、键盘操作和题目切换。

验收标准：

- 各难度显示范围与规格一致。
- 目标答案不出现在隐藏 DOM 或可访问名称中。
- 题目切换不会残留上一题答案或焦点状态。
- 768px、1024px、1440px 下表格和作答区不溢出。

### 阶段 4：即时反馈与结算页

- 实现提交锁定、正确/错误反馈和自动/手动进入下一题。
- 生成本局结果并计算星级。
- 实现结算页、“再来一局”和返回设置。

验收标准：

- 每题只按首次提交计分。
- 答错时正确答案清晰可见，不能修改后改判。
- 三星速度目标按难度正确应用。
- 再来一局保留设置并生成新的随机题目。

### 阶段 5：自动化测试、响应式和可访问性验收

- 补齐设置页、答题页、矩阵和结算页组件测试。
- 增加乘法模块 E2E Page Object 与核心流程用例。
- 验证平板、桌面、键盘、焦点、颜色对比和控制台状态。
- 确认乘法闯关不会改变现有加减法记录。

验收标准：

- 单元测试、生产构建和 E2E 全部通过。
- 关键操作只用键盘也可完成。
- 页面无未处理异常、控制台错误和 React 警告。
- 原有计算训练、统计和订正 E2E 保持通过。

### 阶段 6：版本更新与发布检查

- 将包版本和页面版本统一更新为 `2.6.0`。
- 同步 README、AGENTS.md、路线图和发布检查清单。
- 执行完整 CI、生产构建和支持设备矩阵验收。
- 创建 `v2.6.0` 标签、GitHub Release 并发布 GitHub Pages。

验收标准：

- 包信息、页面、标签和 Release 版本一致。
- 线上首页、设置、三档答题和结算流程冒烟通过。

## 7. 测试清单

### 7.1 单元测试

- 生成完整 81 题，包含 `1×1`、`3×7`、`7×3` 和 `9×9`。
- 抽取 10、20、50 题时数量正确且无重复。
- 四选一包含唯一正确答案，四项互不重复且均为正整数。
- 简单显示目标行列且排除目标格。
- 中等正确处理中心、边缘和四角目标格。
- 困难不返回任何可见乘积格。
- 分数四舍五入正确。
- 三星正确率和速度边界正确。
- 正确率达到 80% 但未达到三星时为二星。
- 低于 80% 且完成本局时为一星。

### 7.2 组件测试

- 设置页默认值和三种难度说明正确。
- 简单题使用选择项，中等和困难使用数字输入。
- 非法输入不能提交。
- 首次提交后控件锁定。
- 正确、错误反馈内容正确。
- 题目切换清理上一题状态。
- 结算页只展示约定信息。
- 缺少路由状态时返回设置页。

### 7.3 E2E

- 首页进入九九乘法闯关。
- 三种难度均能开始并完成一局。
- 10、20、50 题配置生效。
- 简单显示整行整列，中等只显示相邻格，困难隐藏全部乘积。
- 简单可点击选项作答，中等和困难可用 Enter 提交。
- 答错后显示正确答案并继续下一题。
- 最后一题进入结算并正确显示星级、分数和用时。
- “再来一局”保留设置，“返回难度选择”回到设置页。
- 刷新会话和结算页安全回退。
- 乘法闯关前后 `practice-records` 内容保持不变。
- 768px、1024px、1440px 视口无横向溢出。
- 键盘焦点可见、反馈可播报、控制台无错误。
