# v2.6 九九乘法闯关技术原型与基础模型

## 1. 目标与边界

本文件记录 v2.6 步骤 5“技术原型与基础模型”的实现和验收结果。该步骤建立可供步骤 6 直接复用的乘法领域模块，并通过独立 React 技术原型验证矩阵接线、累计开图和答案防泄露。

本步骤不注册生产路由，不实现完整设置—答题—结算流程，不读写 `localStorage`，不修改现有加减法题目、评价或历史模型。

## 2. 基础模型

领域模块位于 `src/features/multiplication/`，公开能力如下：

| 能力 | 接口 | 约束 |
|---|---|---|
| 配置 | `DIFFICULTIES`、`QUESTION_COUNTS`、`SPEED_TARGETS`、`DEFAULT_MULTIPLICATION_SETTINGS` | 三档难度，10/20/50/81 题 |
| 坐标题目 | `questionFromCoordinateId(id)` | `0–80` 映射完整 9×9 有序坐标 |
| 无放回抽题 | `generateMultiplicationQuestions(count, rng)` | 洗牌坐标编号池，不使用拒绝采样 |
| 四选一 | `generateAnswerChoices(question, rng)` | 唯一正确答案、唯一正整数干扰项 |
| 累计开图 | `recordAnsweredCell(answeredCells, question, value)` | 普通对象、不可变更新、首次提交唯一 |
| 格子键 | `getCellKey(a, b)` | 使用 `a×b`，交换顺序是不同坐标 |
| 矩阵视图 | `buildMatrixCells(input)` | 返回 81 个安全乘积格视图 |
| 评分 | `calculateMultiplicationResult(input)` | 返回分数、平均用时和 1–3 星 |

### 2.1 抽题

抽题先创建 `0–80` 的逻辑坐标编号池，通过 Fisher–Yates 洗牌后截取指定数量，再映射为：

```js
{ a, b, op: '*', answer: a * b }
```

这保证每个有序坐标等概率、单局无重复；81 题模式覆盖整表且无遗漏。随机源允许注入，便于测试和技术原型生成确定性题序。

### 2.2 累计开图

`answeredCells` 是以 `a×b` 为键的普通对象，每条记录包含：

```js
{
  a,
  b,
  answer,
  submittedValue,
  correct,
  order
}
```

记录函数返回新对象，不修改调用方状态。同一坐标二次提交直接拒绝，对称坐标不会被自动写入历史。

### 2.3 矩阵显示优先级

矩阵安全视图严格按以下顺序生成：

1. 当前目标；
2. 已作答历史格；
3. 反馈期间未作答的交换律对称格；
4. 当前难度提示格；
5. 隐藏格。

作答前目标格和隐藏格不包含 `value`，其可访问名称也不包含正确答案。React 组件只渲染视图模型明确提供的可见字段。

## 3. 技术原型

入口：

```text
http://127.0.0.1:5173/that-math-things/docs/prototypes/v2.6-multiplication-tech.html
```

启动方式：

```bash
npm start
```

原型直接导入领域模块和 `MultiplicationMatrix`，不复制题目或矩阵算法。评审工具支持：

- `768 / 1024 / 1440` 宽度；
- 简单、提升、挑战；
- 10、20、50、81 题；
- 确定性或随机题序；
- 模拟答对、答错和切题；
- 累计开图早期、高密度、对称格已作答、81 题最后一题和 81/81 全表完成。

技术原型不属于产品界面，不进入生产路由和构建入口。
