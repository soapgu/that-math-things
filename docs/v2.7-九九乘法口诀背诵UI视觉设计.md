# v2.7 九九乘法口诀背诵 UI 视觉设计

## 1. 设计目标与状态

本文件是 v2.7 步骤4“UI视觉设计”的交付物。它以已验收的低保真状态机为交互基线，定义统一设置页、单行背诵控制栏、双表状态、语音、完成反馈、响应式和无障碍视觉规则，并作为步骤5技术原型的强制输入。

设计方向为“安静的数学练习纸”：延续 v2.6“清爽数学乐园”的品牌框架，减少闯关感，以青绿色表达“已经背过”，品牌蓝表达“当前与可操作”。

当前状态：**步骤4已完成并通过用户视觉体验与Firefox人工复核**。

## 2. 高保真原型

原型文件：[prototypes/v2.7-recitation-high-fi.html](./prototypes/v2.7-recitation-high-fi.html)

高保真原型通过同源 iframe 加载低保真文件，在完整状态机上叠加视觉层，不复制会话、语音、确认和映射逻辑。评审工具条不属于产品界面。

## 3. 设计原则

1. **两张表是主角**：装饰不能压过当前口诀、乘法关系和45句进度。
2. **蓝色表示当前，青绿表示已背**：不将已背描述为语音判断正确。
3. **左右反馈各守边界**：乘法格用青绿底和✓；口诀格与分组标题只用青绿底和字重。
4. **反馈不改变尺寸**：状态、动效、字体和Firefox最小内容规则均不得改变10行轨道。
5. **文字与形状共同表达**：当前、可选、关联、已背和禁用不只依靠颜色。
6. **完成反馈克制**：45/45只播放一次柔光，不使用彩屑、星级或评分。

## 5. 页面与组件

### 5.1 全局与设置页

- 深色渐变顶栏、页面坐标纸纹理、12–16px圆角和轻阴影与v2.6一致。
- 设置页“闯关/背诵”Tab使用品牌蓝选中线；闯关原有难度与题量视觉不改变。
- 背诵入口根据无会话、继续和45/45显示开始、进度、上次方式和重新开始。

### 5.2 单行控制栏

- 顺序固定为返回、模式、当前口诀、语音、确认、进度和重置。
- 当前算式和中文口诀使用深蓝灰粗体；分隔点使用青绿色。
- 领读中突出“停止领读”，确认保持禁用；语音不可用使用中性禁用按钮。
- 进度条高3px，始终使用品牌蓝，不新增第二行。

### 5.3 双表状态

| 状态 | 乘法表 | 口诀表 |
|---|---|---|
| 未背 | 白底、不显示乘积 | 白底、显示不泄露结果的口诀占位 |
| 可选 | 白底、蓝色“可选”、悬停内环 | 不作为选择入口 |
| 当前 | 浅蓝斜纹、蓝色双线 | 浅蓝斜纹、蓝色双线、完整口诀 |
| 交换律关联 | 青绿浅底、青绿虚线 | 不单独增加关联格 |
| 已背 | 青绿浅底、结果和✓ | 较深青绿浅底、完整口诀、无✓ |
| 分组完成 | 不适用 | 标题使用已背底色和字重、无✓ |
| 禁用 | 保留已展开内容，不能选择 | 已背格保持可读 |

分组标题状态由45句完成集合派生，不新增会话字段。左侧乘法格和右侧口诀格的非颜色反馈刻意不同，避免把“展开结果”和“整组背完”混为一类标记。

## 6. 响应式与跨浏览器

| 视口 | 布局 | 规则 |
|---|---|---|
| `768×1024` | 上下 | 单行控制栏使用短文案，乘法格约72px正方形 |
| `1024×768` | 上下 | 乘法表居中约650px，乘法格约62px正方形 |
| `1440×900` | 左右 | 内容宽1400px，面板573px、网格532px、10行逐线对齐 |
| `1920×1080` | 左右 | 仍使用1400px居中布局，不继续放大表格 |

1440与1920显式锁定面板的最小、实际和最大高度；网格使用固定伸缩基准、最大高度和10个 `minmax(0,1fr)` 轨道，直接子项设置 `min-block-size:0`。这组约束必须同时保留，以消除Firefox按最小内容撑高口诀格的差异。

## 7. 动效与降级

| 动效 | 时长 | 行为 |
|---|---:|---|
| 当前句进入 | `220ms` | 轻微淡入和2px上移复位 |
| 新完成格 | `240ms` | 仅新增口诀格和一个或两个乘法格轻量展开 |
| 按钮反馈 | `140ms` | 悬停上移1px，按下缩放至0.98 |
| 45/45柔光 | `680ms` | 两个表格面板同时柔光一次，不改变尺寸 |

`prefers-reduced-motion: reduce` 或评审工具的减少动态效果开启时，全部动效和过渡取消，状态立即稳定显示。语音不可用、存储失败不改变主流程。

## 8. 自动化证据

- `768 / 1024 / 1440 / 1920` 均无横向溢出，页面脚本没有自身错误。
- 1440/1920面板与网格维持573px/532px，10行边界误差不超过1px。
- 1024/768继续上下排列，乘法格保持正方形。
- 口诀表保持9个分组标题、45个有效格和36个空格；乘法表保持81个业务格。
- 12/45完成前四组，44/45只缺第九组，45/45九组全部完成。
- 未背乘法格的可见文本和辅助文本不包含乘积。
- 语音不可用、存储失败、重置确认和减少动态效果状态可用。

Codex内置浏览器会对同源iframe评审容器输出一条来自调试注入的 `MutationObserver` 环境错误；同结构的v2.6高保真原型可稳定复现，直接打开低保真页面则没有该错误。v2.7高保真源码不使用 `MutationObserver`，视觉同步使用iframe文档内的点击、选择和键盘事件完成。正式Chrome/Firefox人工验收不应出现此环境提示。

Firefox人工复核：

1. 1440/1920两侧面板、网格和10条行线对齐；
2. 中文口诀没有裁切或异常换行；
3. 单行控制栏按钮不溢出；
4. 当前蓝、已背青绿、分组完成底色层级清楚；
5. 45/45柔光不改变布局。

## 9. 用户体验确认

1. 设置页是否能清楚区分闯关和背诵；
2. 单行控制栏是否紧凑且当前口诀突出；
3. 青绿色是否自然表达“已经背过”而不是“答对”；
4. 左侧✓与右侧纯底色的反馈边界是否清楚；
5. 当前、可选、交换律关联和禁用状态是否容易辨认；
6. 分组标题只在整组完成后变化是否符合预期；
7. 1440/1920首屏密度和双表对齐是否稳定；
8. 768/1024上下滚动与触控尺寸是否舒适；
9. 语音与重置操作的主次是否明确；
10. 45/45柔光是否克制且有完成感。

用户已确认整体视觉、蓝色当前态、青绿色已背态、左右反馈边界、单行控制栏、双表10行对齐、四档响应式和45/45克制柔光符合预期。Firefox人工复核通过，步骤4完成，下一步进入步骤5“技术原型与基础模型”。
