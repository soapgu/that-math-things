# v2.6 九九乘法闯关 UI 视觉设计

## 1. 设计目标

本文件是 v2.6 步骤 4“UI 视觉设计”的交付物。它以已验收的低保真原型为交互基线，定义首页入口、设置、三档答题、即时反馈、退出确认和结算的视觉语言，并作为步骤 5 技术原型和后续生产实现的视觉输入。

设计方向为“清爽数学乐园”：保持现有 Ant Design 产品结构的清晰和可实现性，通过坐标纸、数字轨道、轴滑块、交叉光线和柔和色块增加儿童友好感，不引入角色插画或与当前范围不一致的关卡地图。

当前状态：**已完成并通过体验确认**。

## 2. 高保真原型

原型文件：[prototypes/v2.6-multiplication-high-fi.html](./prototypes/v2.6-multiplication-high-fi.html)

推荐从项目根目录启动：

```bash

```

浏览器打开：

```text
http://127.0.0.1:4173/docs/prototypes/v2.6-multiplication-high-fi.html
```

高保真原型通过同目录低保真交互基线加载完整状态机，再叠加独立视觉层和首页入口，以保证步骤 3 已验收的交互行为不被复制偏差破坏。两个原型均为文档资产，不依赖 React、生产路由或 localStorage。

评审工具条可切换：

- 首页、设置、准备作答、正确反馈、错误反馈、最后一题、退出确认和结算；
- 简单、提升、挑战；
- `768 / 1024 / 1440` 三种支持宽度。

评审工具条不属于产品界面。

## 3. 设计原则

1. **矩阵是主角**：装饰不能压过矩阵、算式和答案入口。
2. **难度改变支架，不改变流程**：蓝、橙、紫只帮助识别难度，不表达好坏。
3. **正确和错误语义独占**：绿色只表示正确，红色只表示错误。
4. **状态不只依靠颜色**：同时使用边框、图标、文字和形状。
5. **反馈不改变布局**：矩阵固定为 10×10 等分轨道，提交前后外框和格子尺寸一致。
6. **动效服务理解**：先定位滑块、再发射光束并照亮提示，解释乘数坐标；对称格延迟出现解释交换律，其余动效保持克制。

| `text-secondary` | `#595959` | 正文、说明 |
| `text-weak` | `#8C8C8C` | 辅助文字 |
| `border` | `#D9D9D9` | 默认边框 |
| `success` | `#237804` | 正确文字、关键边框，满足浅绿底普通文字对比 |
| `success-accent` | `#52C41A` | 正确状态装饰，不单独承载文字 |
| `success-soft` | `#F6FFED` | 正确背景 |
| `error` | `#CF1322` | 错误前景、边框 |
| `error-soft` | `#FFF2F0` | 错误背景 |

| `medium-soft` | `#FFF7E6` | 提升浅背景 |
| `hard` | `#722ED1` | 挑战难度 |
| `hard-soft` | `#F9F0FF` | 挑战浅背景 |

光束和提示数字采用同色相分层：

| 难度 | 提示数字 | 光束核心 | 光束光晕 |
|---|---|---|---|
| 简单 | `#0958D9` | `#91CAFF` | 浅蓝约 28% |
| 提升 | `#873800` | `#FFD591` | 浅橙约 30% |
| 挑战 | `#531DAB` | `#D3ADF7` | 浅紫约 30% |

光束在 `FIRING` 阶段保持约 45–55% 的中心可见强度，`READY` 阶段降至约 16–20%；提示数字始终使用深色并承担主要可读信息。

白底正文、难度前景和语义前景均按 WCAG AA 普通文字目标选择。浅色只承担背景，不单独承载状态。

### 4.2 字体与字号

- 字体栈：`system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif`。
- 算式、计时、分数和矩阵数字使用 `font-variant-numeric: tabular-nums`。
- 页面标题 `30px / 700`。
- 当前算式：`32–48px / 700`，随可用宽度收敛。
- 卡片标题：`18–20px / 700`。
- 正文和按钮：最低 `14px`。
- 矩阵数字：支持视口内最低 `13px`。
- 辅助说明：`12–13px`，不得承载唯一关键操作信息。

### 4.3 尺寸与表面

- 间距采用 `4px` 基线，常用值为 `8 / 12 / 16 / 24 / 32px`。
- 主卡片圆角 `12px`，页面外框 `16px`，按钮和输入框 `8px`，矩阵 `14px`。
- 主卡片阴影：`0 8px 24px rgb(31 35 41 / 8%)`。
- 应用外框阴影：`0 12px 36px rgb(31 35 41 / 14%)`。
- 弹窗阴影：`0 18px 48px rgb(0 0 0 / 24%)`。
- 阴影只表达层级，不用于普通矩阵格。

### 4.4 图标

- 生产实现优先使用 Ant Design Icons；原型允许使用 CSS 几何图形。
- 首页九九乘法图标为 3×3 小矩阵，中心格实心，表达交叉定位。
- 正确使用 `✓ + 正确文字`，错误使用 `✕ + 错误文字`。
- 交换律对称格使用 `⇄` 和虚线边框。
- 图标不能替代按钮文字、正确算式或错误说明。

## 5. 页面视觉

### 5.1 全局导航

- 延续深色顶栏，使用 `#102A43 → #164E87` 的低对比渐变。
- 当前菜单同时使用浅蓝底、底部高亮线和 `aria-current`。
- `768px` 显示“那些数”、隐藏版本号，保留四项菜单。
- `1024px` 和 `1440px` 恢复完整品牌与版本位置。

### 5.2 首页入口

- 三个入口保持同尺寸、同操作层级。
- 九九乘法卡片使用浅蓝渐变背景和 3×3 矩阵图形。
- 文案：“沿着数字轨道找到交叉点，挑战完整九九表。”
- 不扩大或跨栏展示，不把尚不存在的关卡解锁画进入口。

### 5.3 设置页

- 三张难度卡使用左侧识别条、浅色背景、粗边框和选中环。
- 简单蓝、提升橙、挑战紫；选中状态仍保留文字与 `aria-pressed`。
- 题量按钮使用统一品牌蓝，不跟随难度换色。
- “开始闯关”为唯一主按钮。

### 5.4 答题页

- 左侧矩阵放置在白色悬浮卡片上；右侧操作区使用独立白色卡片。
- 页面底层使用极浅 `24px` 坐标纸纹理，透明度不超过 `3%`。
- 右侧顺序固定为状态、算式、作答、反馈。
- 状态文字使用当前难度前景色；算式始终使用主文字色。
- 反馈区高度固定，`READY` 时也保留占位。

### 5.5 结算页

- 星级是第一视觉重点，使用金色和依次点亮动效。
- 分数使用品牌蓝；正确数、总题数、作答时间使用三个同质统计卡。
- 主操作“再来一局”，次操作“返回难度选择”。
- 仅三星显示少量彩屑；不加入历史、错题、统计或订正入口。

## 6. 矩阵状态

| 状态 | 背景 | 边框和标记 | 文字 |
|---|---|---|---|
| 表头 | 冷灰蓝 | 1px 网格线 | 深蓝灰、加粗 |
| 隐藏格 | 白色 | 1px 网格线 | 无乘积 |
| 提示格 | 当前难度浅色 | 默认网格线 | 当前难度前景色 |
| 目标格 | 当前难度浅色 | 3px 实线、交叉光线 | 提交前留空 |
| 格内输入 | 白色 | 当前难度 2px、焦点环 | 当前难度前景色 |
| 正确格 | 成功浅绿 | 3px 成功实线、`✓` | 正确答案 |
| 错误格 | 错误浅红 | 3px 错误实线、`✕` | 正确答案 |
| 对称格 | 成功浅绿 | 3px 成功虚线、`⇄` | 相同正确答案 |

目标格、对称格和反馈图标采用覆盖定位，不参与网格轨道尺寸计算。

## 7. 组件状态

| 组件 | 默认 | 悬停/按下 | 选中或焦点 | 禁用/反馈 |
|---|---|---|---|---|
| 难度卡 | 白底、识别条 | 上移 1px | 难度边框、浅底、外环 | `aria-pressed` 同步 |
| 题量按钮 | 白底灰边 | 上移/缩放 | 品牌蓝边和浅底 | 灰字、无阴影 |
| 四选一 | 白底灰边 | 上移 2px、浅蓝底、数字放大 1.05；按下缩放 0.98 | 品牌蓝边、柔光及 3px 焦点环 | 正确绿 `✓`；错选红 `✕` 并同步标绿正确项；其余中性禁用 |
| 格内输入 | 白底难度边 | 不位移 | 3px 半透明品牌焦点环 | 定位/反馈期间不存在或禁用 |
| 主按钮 | 蓝色渐变 | 上移/缩放 | 品牌焦点环 | 灰底、无阴影 |
| 次按钮 | 白底灰边 | 上移/缩放 | 品牌焦点环 | 灰字 |
| 导航 | 透明 | 半透明白底 | 浅蓝底和底线 | 不适用 |

所有可操作控件的触控高度不低于 `44px`。

四选一反馈状态通过 `data-choice-state` 固化：

| 值 | 视觉 | 语义 |
|---|---|---|
| `idle` | 默认、悬停、按下、焦点 | 尚未作答 |
| `selected-correct` | 成功浅绿、深绿边框、`✓` | 孩子选择且正确，`aria-pressed=true` |
| `selected-wrong` | 错误浅红、深红边框、`✕` | 孩子选择但错误，`aria-pressed=true` |
| `correct-answer` | 成功浅绿、深绿边框、`✓` | 答错时指出正确选项，`aria-pressed=false` |
| `inactive` | 中性灰、禁用 | 未选择的其他选项 |

反馈状态由当前题首次答案记录重建，不依赖提交前按钮节点，因而不会在重新渲染、退出确认或等待切题时丢失。

## 8. 动效规范

| 动效 | 时长 | 行为 |
|---|---:|---|
| 轴滑块定位 | `600ms` | 从上一题坐标移动到当前两个乘数；期间无光束 |
| 光束发射与显数 | `800ms` | 滑块到位后同时发射，贯穿行列并按路径显现允许提示 |
| 按钮反馈 | `140ms` | 按下缩放至 `0.98` |
| 正确答案 | `320ms` | 轻微放大后复位 |
| 错误答案 | `320ms` | 水平轻摇，不超过 `3px` |
| 对称格 | `360ms + 120ms delay` | 在目标格之后淡入缩放 |
| 星级 | `700ms` | 依次点亮 |
| 三星彩屑 | 不超过 `1200ms` | 少量、一次性、不遮挡操作 |

`prefers-reduced-motion: reduce` 下取消位移、缩放、摇动、星级过渡和彩屑，直接显示最终状态；定位等待、反馈 2 秒停留和操作能力保持一致。

横纵光束宽度约为单格的 `50%`，中心亮、两侧柔和渐隐，并带低强度模糊光晕。作答期间光束降低亮度但不消失；提示数字保持可读。简单显示完整行列，提升只显示相邻格，挑战只在交叉完成后显示输入框。

## 9. 响应式标注

| 预览 | 应用内容 | 矩阵 | 右侧面板 |
|---|---|---:|---:|
| `768×1024` | 左右两栏 | 约 `430–440px` | 约 `240–250px` |
| `1024×768` | 左右两栏 | `560px` | 约 `350px` |
| `1440×900` | 居中最大宽度 | `560px` | 约 `540px` |

- 支持宽度内不切换成纵向答题布局。
- 矩阵最大 `560px`，宽屏增加留白和反馈可读性，不放大到压迫右栏。
- 10 行、10 列均使用 `minmax(0, 1fr)` 等分。
- 提交、焦点、反馈和交换律标记不得改变矩阵外框或单元格尺寸。

## 10. 自检与体验确认

自动化自检必须覆盖：

- 首页三个入口同层级，九九乘法入口可进入设置。
- 三档视口导航完整、无横向溢出、主要答题内容位于首屏。
- 三档颜色、提示格数量和格内输入方式准确。
- 定位中不可提交且不计时。
- 滑块到位前不出现光束；光束发射前不出现提示数字或作答控件。
- 正确、错误和交换律对称格同时依靠颜色与非颜色标记。
- 四选一悬停、按下和键盘焦点清晰；答对保持绿 `✓`，答错保持红 `✕` 并同步指出绿色正确项。
- 提交前后矩阵及单元格尺寸一致。
- 键盘焦点可见，隐藏格不泄露答案。
- 减少动态效果规则存在，页面无 JavaScript error。

体验确认重点：

1. “清爽数学乐园”是否与现有产品协调；
2. 蓝、橙、紫是否容易区分且不带能力评价；
3. 坐标纸、滑块和交叉光线是否清晰而不过度装饰；
4. 正确、错误和交换律反馈是否一眼可辨；
5. 动效强度和三星结算氛围是否合适。

完成自检并通过用户体验确认后，步骤 4 标记完成，步骤 5“技术原型与基础模型”成为下一步。

## 11. 当前自检结果

- 首页三个入口保持同尺寸，九九乘法入口可进入设置页；评审工具可从其他状态独立返回首页。
- `768 / 1024 / 1440` 三档评审宽度中，应用外框 `scrollWidth` 不超过自身宽度，导航保持完整。
- `768` 评审宽度保持左右两栏；真实 `768px` 视口下矩阵目标约为 `430–440px`。
- 矩阵固定渲染 100 格；简单显示交叉路径，提升显示 4 个相邻提示，挑战显示 0 个提示。
- 简单、提升、挑战目标边框分别使用蓝、橙、紫；错误目标和反馈区同时使用红色、`✕` 与完整错误文字。
- 提升和挑战的输入框位于目标格；非对角线题提交后显示带 `⇄` 的对称格。
- 高保真覆盖样式将矩阵容器锁定为 `1:1`，提交前后宽高一致，不受反馈卡内容影响。
- 定位内部拆分为 `SLIDING / FIRING / REVEALED`，总时长约 `1.4 秒`；光束约半格宽并贯穿完整矩阵。
- 浏览器分阶段采样确认：`SLIDING` 时光束高度为 0、提示和作答控件数量为 0；`FIRING` 时光束伸展且提示逐步出现；`REVEALED` 时简单显示 16 个路径提示和 4 个选项。
- 提升在 `REVEALED` 后只显示 4 个相邻提示和 1 个格内输入；挑战显示 0 个提示，并仅在交叉完成后创建输入框。
- 光束在作答阶段降至低亮度，提交反馈时重新增强；矩阵提交前后均保持 `1:1` 且尺寸一致。
- 三档光束改用浅色核心和低强度光晕，提示数字使用同色相深色；四选一反馈状态由答案记录恢复，重新渲染不丢失。
- 浏览器确认简单/提升/挑战分别使用 `#0958D9/#91CAFF`、`#873800/#FFD591`、`#531DAB/#D3ADF7` 的数字/光束组合。
- 四选一悬停实测为上移 2px、浅蓝底、品牌蓝边、柔光和数字缩放 1.05；四个按钮始终保持相同尺寸。
- 答错实测保留红色 `✕` 错选项和绿色 `✓` 正确项；答对只保留绿色 `✓` 已选项。`data-choice-state`、`aria-pressed` 和可访问名称均与可见状态一致。
- 用户已确认整体完成度、光束显现、同色相配色层级和四选一反馈状态符合预期；步骤 4 正式完成。
- 正文、次文字、提升、挑战和错误文字对比均达到 WCAG AA；正确文字改用深绿 `#237804`，亮绿只作装饰。
- HTML 内联脚本通过语法检查，`git diff --check` 通过；步骤 4 仍等待用户视觉体验确认。
