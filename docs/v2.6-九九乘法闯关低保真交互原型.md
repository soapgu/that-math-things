# v2.6 九九乘法闯关低保真交互原型

## 1. 原型目标

本原型用于执行 v2.6 步骤 3“低保真交互原型”，验证已经确认的页面流程、左右答题布局、乘法轴定位、9×9 矩阵信息密度、格内作答、交换律反馈、切题、退出确认和结算流程。

原型采用灰度线框，只表达结构、状态、尺寸和操作。配色、插画、品牌图形、阴影、庆祝效果等最终视觉不在本步骤确定。

当前状态：**已完成并通过体验确认**。

## 3. 原型范围

### 3.1 正常体验模式

- 设置页选择简单、提升、挑战。
- 选择 10、20、50、81 题；81 题用于完成整张九九乘法表。
- 开始闯关并按确定性代表题完成一局。
- 简单使用右侧四选一；提升、挑战直接在矩阵目标格输入。
- 每题先播放约 1.4 秒的“滑块定位→光束发射→提示显现”，定位结束后才开始作答计时。
- 提交后同时显示目标格和交换律对称格；对角线题只强化一个格子。
- 正确和错误均显示即时反馈。
- 普通题 2 秒自动切换，也可以手动提前进入下一题。
- 最后一题只能手动“查看结果”。
- 结算页可以再来一局或返回难度选择。
- 答题中点击顶部导航会显示离开确认。

### 3.2 评审工具条

页面顶部虚线区域是原型专用评审工具，不属于产品界面，也不会进入正式实现。

评审工具可以快速切换：

- `768 / 1024 / 1440` 三种预览宽度；
- 简单、提升、挑战三档难度；
- 设置、准备作答、正确反馈、错误反馈、最后一题、离开确认和结算状态。

快速状态用于避免评审者必须完成 10–50 题才能查看末尾状态。正常体验模式仍可完整走通产品流程。

## 4. 线框与响应式规则

### 4.1 顶部导航

- `768px`：品牌显示“那些数”，隐藏版本号，四个导航项保持单行。
- `1024px`、`1440px`：显示完整品牌“那年那数那些事”和版本位置。
- 答题期间点击导航先进入离开确认；设置页和结算页可直接离开。

### 4.2 设置页

- 标题使用“九九乘法”。
- 难度卡片和题量按钮使用边框、粗细和文字标识选中状态，不依赖颜色。
- “开始闯关”是唯一主操作。

### 4.3 答题页

支持宽度均使用左右布局：

- 左侧固定为 9×9 矩阵及横纵轴滑块、交叉射线。
- 右侧依次为“题号 · 作答用时”紧凑状态、当前算式、作答与提交、固定高度反馈区。
- 移除横向进度条，降低纵向高度和滚动需求。
- `768px` 下左栏至少 `430px`，右栏至少 `230px`；更宽视口优先放大矩阵至 `560px`。

矩阵包含左上角乘号、1–9 列标题、1–9 行标题和 81 个乘积格，共 100 个格子。

新题从上一题的轴坐标滑向当前两个乘数，首次从两个轴的 `1` 开始。滑块用约 `600ms` 完成定位，到位后才同时发射约半格宽的横纵光束；光束用约 `800ms` 贯穿完整矩阵，允许的提示乘积随光束依次显现。作答时数字保留、光束淡化，提交后光束强化。`prefers-reduced-motion: reduce` 下跳过位移和逐格显现，直接呈现相同定位结果。

简单显示完整目标行列；提升只点亮目标上下左右相邻格，即使光束经过其他格子也不显示乘积；挑战不显示乘积，并在光束交叉完成后才创建目标格输入框。

### 4.4 三档矩阵

| 难度 | 可见内容 | 作答 |
|---|---|---|
| 简单 | 目标整行、整列的其他乘积 | 四选一 |
| 提升 | 目标上下左右实际存在的相邻乘积 | 目标格内正整数输入，右侧提交 |
| 挑战 | 不显示其他乘积 | 目标格内正整数输入，右侧提交 |

提交后目标格填入正确答案，并同时使用 `✓` 或 `✕` 与反馈文字表达结果。实际作答格永久留在本局矩阵中，形成逐步开图；非对角线题的对称格仅在反馈期间临时显示，切题后恢复，除非该坐标此前已经实际作答。

三档都始终显示历史格；尚未作答格才遵守简单整行整列、提升相邻、挑战隐藏的提示范围。显示优先级为当前目标、历史格、临时提示、隐藏格。

简单模式四选一由本题首次答案记录驱动反馈状态，重新渲染后仍保留：

- 答对：孩子选择显示 `✓`，其他选项中性禁用。
- 答错：孩子选择显示 `✕`，正确选项同时显示 `✓`，其余选项中性禁用。
- `aria-pressed` 只标记孩子实际选择；可访问名称分别说明“你的选择，回答正确/错误”和“正确答案”。
- 新题初始化时清理上一题选择状态。

### 4.5 反馈与结算

- 反馈出现时矩阵、算式、作答区和反馈区的两栏结构保持不变。
- 两栏轨道不受反馈文字的最小内容宽度影响；对错符号覆盖在目标格内，不参与格子尺寸计算。
- 非最后一题显示“下一题”和自动切题说明。
- 最后一题显示“查看结果”，不启动自动切题。
- 结算只展示星级、分数、正确题数、总题数和作答用时。

## 5. 自动化自检

### 5.1 视口与导航

使用 Playwright Chromium 检查：

| 视口 | 页面宽度 | 横向滚动 | 品牌状态 | 导航状态 |
|---|---:|---|---|---|
| `768×1024` | 768 | 无 | 显示“那些数”，隐藏完整品牌 | 矩阵约 `437px`，右栏约 `249px`，四项导航完整 |
| `1024×768` | 1024 | 无 | 显示完整品牌 | 矩阵 `560px`，右栏约 `354px` |
| `1440×900` | 1440 | 无 | 显示完整品牌 | 矩阵 `560px`，右栏 `540px` |

三档视口均没有横向溢出。产品答题主体位于首屏；`1024×768` 的页面额外纵向高度来自原型评审工具条和线框说明，不属于产品界面。浏览器控制台未发现 JavaScript error。

### 5.2 交互与状态

- 矩阵渲染 100 个格子。
- 定位动效期间不能提交且不计入作答时间。
- 定位期间状态显示“定位中”，先完成滑块移动，再发射光束；矩阵中没有输入框或答案选项。约 1.4 秒后状态变为“作答 0 秒”并启用作答。
- 提升、挑战可在目标格输入并通过 Enter 提交。
- `6×7=42` 正确反馈内容与目标格状态一致。
- `6×7` 提交后同时显示 `7×6` 对称格；`8×8` 只显示一个对角线格。
- 评审工具可直接检查累计开图早期、高密度、对称格已作答、81 题最后一题和 81/81 全表完成状态。
- 81/81 状态包含 80 个历史格和 1 个当前反馈格，合计完整打开 81 个乘积格，并继续显示“查看结果”。
- 手动“下一题”后等待超过 2 秒，仍只前进到第 2 题，没有重复切题。
- 自动等待 2 秒可从第 1 题进入第 2 题。
- 挑战难度的隐藏乘积格可见文本为空，不包含乘积答案。
- 答题中点击导航会显示离开确认。
- 取消离开后题号保持不变。
- 最后一题按钮为“查看结果”，点击后进入结算。
- `prefers-reduced-motion: reduce` 下上述流程保持可用。

### 5.3 布局稳定

在 `768×1024` 下，`6×7` 提交前后矩阵边界均为：

```text
x = 34
y = 171.5
width ≈ 436.5
height ≈ 436.5
```

提交前后矩阵位置和尺寸一致，右侧固定反馈区域承担反馈内容，不推动矩阵或算式换行。整页 `scrollWidth = 768`，无横向滚动。

针对体验反馈补充在 `730×726` 的窄评审窗口复检：提交前后矩阵均约为 `412.4×412.4px`，目标格均约为 `41.1×41.1px`。10 行使用固定等分轨道，反馈文字及 `✓/✕` 标记不会再改变任一行或矩阵外框尺寸。

## 7. 用户体验确认清单

请优先体验以下路径：

1. 在评审工具条切换到 `768`，确认左右布局是否减少纵向滚动，顶部导航是否完整。
2. 观察新题横纵轴滑块和交叉射线，判断定位关系是否清晰且不过度打扰。
3. 简单难度查看 `6×7`，判断交叉路径上的整行整列是否提供帮助。
4. 提升、挑战难度直接在目标格输入，判断格内输入和右侧提交是否自然。
5. 提交 `6×7` 后确认 `7×6` 对称格是否能清楚表达交换律，再查看 `8×8` 对角线反馈。
6. 故意答错一题，判断 2 秒反馈是否足够阅读交换律说明。
7. 在反馈出现后立即点击“下一题”，确认节奏是否自然。
8. 使用顶部导航触发离开确认，再选择继续闯关。
9. 通过评审工具条切换到最后一题和结算，检查衔接。
10. 切换“累计开图·高密度”和“81/81·全表完成”，确认历史答案清楚但不会压过当前目标。
10. 尝试只用键盘完成选择、格内输入、提交和下一题。
